# Stage 5A：受控、文件级办公自动化

本阶段扩展同一个项目，不是另一个 Agent，也不是鼠标键盘控制 Word/Excel。
所有真实文件操作由确定性代码执行。模型只能提出结构化建议；没有 Python、VBA、COM、
PowerShell、CMD、宏运行、外部连接刷新、强制解锁、关闭 Office 或提权能力。

## 实际格式矩阵

| 格式 | 读取 | 新建 / 另存为 | 原地编辑 | 边界 |
|---|---|---|---|---|
| TXT / Markdown | 是 | 是 | 是 | UTF-8、UTF BOM；整段替换、追加；不渲染或执行 Markdown |
| JSON | 严格解析 | 是 | 是 | 重复键/非有限数值拒绝；已有 JSON Pointer 更新；十进制值不经 float 重写 |
| CSV | 是 | 是 | 是 | 明确逗号/分号/Tab 方言；单元格、列名、空行过滤、文本排序；不猜列类型 |
| XLSX | 静态类型化读取 | 简单工作表 | 有限 | 精确单元格编辑、有限公式、数值倍率、添加/重命名工作表；不计算公式 |
| DOCX | 段落 / 表格 | 简单文档 | 有限 | 单 run 段落、标题、普通表格；复杂格式、合并表格、批注、修订等只读 |
| PDF | 静态页文本 | 派生 TXT/Markdown/DOCX | 不支持 | 不编辑 PDF；扫描页/空页提示 OCR 未实现；不执行动作、链接或附件 |
| DOCM / XLSM | 谨慎静态读取 | 不支持 | 不支持 | 宏永不执行、宏格式不保存；伪装成 DOCX/XLSX 的宏包拒绝 |
| PPTX / PPTM | 仅识别包与警告 | Deferred | Deferred | 不声称实现演示文稿内容编辑 |

XLSX 公式不由 Python 重算，缓存结果不能冒充新的计算结果。已有公式不能被静默转换为值。
公式白名单仅包含本地单元格、算术及 SUM/AVERAGE/MIN/MAX/COUNT/ROUND，复杂公式使文档只读。
受保护工作簿/工作表、外部链接、数据连接、嵌入对象和未知复杂功能没有“强制继续”入口。
合并单元格可展示；对合并区域的编辑拒绝。含公式的工作表重命名拒绝。

## 用户路径

1. 在“办公文档”选择明确文件，阅读 R0 范围并确认。此时仅授权那些文件，不包括父目录。
2. 读取在后台完成。列表默认不勾选；点击文件可查看来源引用和真实支持情况。
3. 勾选输入，并单独选择输出文件。默认 `SAVE_AS`，目标已存在就拒绝。
4. 用有限操作编辑器指定 `body`、`p:0`、`s:0:A1` 等真实引用与新值。多个单元格用多个精确操作。
5. 生成 Preview。检查之前/之后、类型、公式、路径、数量、风险及恢复条件。
6. 新建 / 另存为通常 R1，计划确认后才能保存。高影响批次升为 R2_HIGH_IMPACT。
7. `EDIT_IN_PLACE` 和 Restore 为 R2：先单独确认 R1 加密备份，再确认包含备份的新计划，
   执行前完成短时、对象特定的即时确认。创建备份本身不批准编辑。
8. 成功必须由最终路径重新打开、文件身份、完整哈希和结构化内容共同验证。

当前 GUI 的 CSV 输入使用逗号。分号/Tab 可通过核心 `prepare_read(..., delimiter=...)` 显式指定。
新建 XLSX 使用 CSV 文本创建简单表，DOCX 使用逐行段落。PDF 可另存为支持的派生文本格式。
多个普通 XLSX 可合并到一个新工作簿：必须各只有一张表、表头和列数精确一致、没有公式。
不支持通用多输出批次；混合/不支持输入整体阻止，不跳过失败文件或行后报告全部成功。

## 身份、授权和最终校验

`OfficeDocumentIdentity` 绑定 Windows 卷、文件 ID、大小、创建/修改时间、属性、硬链接数、
只读/云盘警告及完整 SHA-256。重解析点、网络/映射网络盘、系统/应用数据和既有敏感目录禁止。
允许的云同步位置必须为普通、完全本地、非 reparse 文件；展示 caution，不承诺云端同步原子性。
网络写入 Deferred。Office 只接受会话中用户创建的 READ / OUTPUT UUID，不接受模型生成路径。
`DocumentTargetResolver` 只在已授权读取的文档中找候选；同名不自动选中，最终必须选精确 UUID。

文件内容从持有的 Windows handle 读取并计算哈希；祖先目录保持打开且不分享删除权限，
原文件不分享写/删除权限。提交前在这些 handle 上重读哈希，拒绝同路径换文件。
普通本地 NTFS 是写入要求；只读、硬链接、额外数据流、压缩/加密/稀疏/未下载文件拒绝原地替换。
新输出的权限与原件不同也会拒绝原地替换，避免丢失自定义访问控制。

## 解析与预算

固定私有解析进程在接收内容前加入 Windows Job，默认内存 512 MiB、最多一个进程、30 秒。
只传递有界 JSON 与字节，没有文件路径、命令或 pickle 结果。解析与序列化都不在 GUI 线程执行。
这不是可抵御任意原生库漏洞的完整 OS 沙箱；进程仍以当前用户运行。依赖漏洞更新仍然必要。
ZIP 目录先检查穿越、重复名称、符号链接、压缩倍率、展开容量、条目数；XML 禁止实体、DTD、
外部引用。Bandit 对 stdlib `Element` 类型导入的一项误报有单行说明，实际解析使用 defusedxml。

默认上限：20 个输入、总输入 200 MiB；文本 10 MiB、Office 包 25 MiB、其他 50 MiB；
200,000 单元格、100,000 行、32 张表、300 页、10,000 个编辑；解析结果缓存序列化预算 32 MiB。
缓存字节预算不是对 Python 对象实际驻留内存的精确测量。单元格/结构上限同样独立执行。
10 个输入 / 5,000 个变更单元格 / 50 MiB 输入触发高影响确认。备份总额默认 2 GiB，不自动清理。

可以在启动前通过 `PC_MANAGER_OFFICE_LIMITS` 提供有限 JSON 配置；超过硬上限拒绝启动，例如：

```powershell
$env:PC_MANAGER_OFFICE_LIMITS = '{"max_files":5,"max_cells":10000,"max_edit_cells":1000}'
uv run python -m pc_manager_agent
```

## 事务、备份与恢复

独立的 `office_records` 和 `office_consents` 是附加 SQLite 表，不修改旧阶段授权。
编辑值、全文和 Diff 只在内存中；数据库保存 UUID、路径/身份、哈希、状态、备份及恢复元数据。
预览 5 分钟；即时确认最长 60 秒。绑定精确计划、输入、输出、风险、Diff、备份与有效期。
双确认消费和 CONFIRMED 状态更新在一个 SQLite 事务中完成；随后派发一次内部短时能力。
工具仍检查活动编排上下文，不能仅伪造一个 UUID 或调用注册表执行写入。

保存顺序：独占创建 `.pcma-<transaction>.pending.<ext>` → 写入 / flush → 关闭后重开验证 →
最后身份检查 → 原件移到 `.pcma-<transaction>.original.<ext>` → 新文件移到目标 → 重新验证。
每次重命名均禁止替换已存在对象。**两次重命名不是整个事务原子替换**；中途竞争/断电可能令目标
暂时不存在。失败时保留原件、临时文件和加密备份，展示真实 FAILED / INTERRUPTED，不自动补做。
取消可能发生在提交后验证期间，因此 CANCELLED / FAILED 不等于磁盘完全没有变化；以历史路径为准。

备份使用当前用户 DPAPI、专属 entropy、CREATE_NEW、回读比较、密文哈希和明文哈希双验证。
没有已验证备份绝不原地写入。原件及备份均不自动删除，计入空间占用；不要承诺省空间。

Restore 要求原事务 COMPLETED、当前目标仍与 Agent 写入的身份完全一致、备份及保留原件完好，
身份摘要同时绑定所有者、组和 DACL；仅权限变化也会使旧确认和恢复条件失效。
重新读取和选择当前目标，并生成独立计划、备份当前版本、两级确认。恢复放回保留的原始对象，
验证原文件 ID、内容、时间和属性；不会把一个新拷贝说成原身份完整恢复。新版本仍留作恢复材料。
任何冲突都停止。FULL 是有这些条件的自动恢复能力，不是无条件保证；原件丢失或损坏时不执行。

新建 / 另存为的 Undo 独立确认后把未被用户修改的输出移到唯一的 `.recovered.<ext>` 同目录文件，
不删除文件；历史保留源/目标身份。用户可手动取回这份材料，不静默覆盖冲突文件。
重启使所有非终态事务 INTERRUPTED、旧确认失效，无自动 commit / retry / restore。

## 可选模型与隐私

`OfficeModelProvider` 与 Windows 管理计划分开，OpenAI 仅是一个适配器。新 Office 适配器固定官方
`https://api.openai.com/v1`，不改动既有用户自定义适配器，不隐式继承其中的第三方地址。
API key 只取已有环境设置；本地默认 disabled。对模型供应商的替换须实现同一协议并展示真实目标。

用户逐项勾选段落/页/单元格片段，最长每段 2,000 字、总 16,000 字，再单独确认精确发送内容。
文件名、完整路径、未选片段、隐含附件不发送。已知密码/密钥/凭据模式阻止发送；这不是完整 DLP。
片段内容永远是不可信数据。模型无注册表/执行能力；未知字段、代码、路径、越界引用拒绝。
摘要目前为带源引用的原文摘录，必须是已选片段的真实子串，不冒充完整长文总结。
数值统计由 Decimal 实施，仅合计显式数值单元格，不把跨列合计解释成业务总额，也不计算公式。

适配器使用结构化 Responses 输出、`store=False`、不提供 tools、不自动重试，超时 30 秒。
`store=False` 不等于零保留，供应商规则及费用需要用户了解。
依据：[结构化输出](https://developers.openai.com/api/docs/guides/structured-outputs)、
[官方数据控制](https://developers.openai.com/api/docs/guides/your-data)。自动化测试不联系真实模型。
审计仅记录标识、哈希关联、数量、稳定错误码和供应商追踪 ID，不保存请求/响应正文或 Diff。
写入结束事件另外关联计划、Preview、备份、两级确认、输入/输出身份摘要、格式、操作类型、
输出模式、真实终态、固定工具名和实测耗时；可据此关联事务，不需要记录完整文档。

## 验证与已知边界

所有测试使用临时合成 DOCX/XLSX/CSV/PDF/TXT 和伪供应商。真实 Win32 测试只操作测试临时文件。
测试覆盖身份替换、备份失败、重命名竞争、恢复冲突、取消、重启、确认绑定/重放、格式安全和 GUI。
核心回归门槛 85%，Office 专项 95%；专项显式包括新 Win32 文件接口，不沿用整体的 Windows omit。
测试命令见开发指南与 CI。函数签名和每个函数作用见 [API 文档](api-office-automation.md)。

没有 OCR、PDF 原地写入、PPTX 编辑、复杂 Word 保真承诺、Excel 计算引擎、网络写入、COM 或桌面控制。
修改 Markdown 不自动渲染，PDF 派生文本不继承活动对象。尚无真实 Office 应用兼容性人工验收或签名发行。
Stage 5B 只作为语音功能的下一阶段建议，本阶段不会自动开始它。
